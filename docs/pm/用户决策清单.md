## A 名称与品牌

**决策**：定下最终中文名 + 英文名（连带决定图标构图与启动画面文案），之后不再改。

| 选项 | 说明 | 代价 |
|---|---|---|
| A1 肌肉守护者 / MuscleKeeper | 与现有 `app.json`、slug、包名、目录名全部对齐；「守护者」贴合家属视角 | 无改名成本；「肌肉」略书面，老人可能读成「肌肉」不顺口 |
| A2 深蹲守护者 / SquatKeeper | 功能直白，一看就知道是练深蹲 | 需改 name/slug/包名/图标文案；名字锁死单一动作，以后加动作要改名 |
| A3 蹲一蹲 / SquatDaily | 最口语、最好记，老人一说就懂 | 辨识度低，桌面图标下易被当成小游戏；同样要改包名 |

图标方向（三选一，与上面命名解耦）：① 简化腿部线条 + 盾牌轮廓（守护感最强）② 单腿下蹲侧影（动作最直白）③ 哑铃轮廓（最通用但与深蹲不直接相关）。统一要求：几何线性、单色主色 + 米白底、24px 仍可辨、不用拟物插画。
副标题：建议「每天蹲一会儿，腿更稳」（启动画面与「关于」各一处）。

**我的推荐**：**A1「肌肉守护者 / MuscleKeeper」+ 图标方向 ① 腿形护盾**。理由：①零改造成本（名称、slug、包名、远端仓库名已一致，改 A2/A3 要同步改 4 处且已截图资产作废）；②「守护者」正好对上「子女给爸爸装」的场景，比「深蹲」更像一个能长期用的东西；③四个字两个词，老人认得全，不出现多音字和生僻字；④腿形 + 盾一笔画清，缩到桌面小图标还认得出。

**若不选则默认**：沿用现状 A1，包名 `com.musclekeeper.app` 不动，图标按方向 ① 出 192/512/180 三张。

## D 数据导出

**决策**：这一版要不要把训练记录导出成文件（给家属看长期变化）。

| 选项 | 说明 | 代价 |
|---|---|---|
| D1 暂不做 | 数据只留本机，设置「关于」里写明「记录只存在这台手机上」 | 0 开发量；换手机、清缓存、清数据后记录全丢，家属拿不到 |
| D2 CSV 导出到文件 | 统计页底部加「导出记录」，生成 CSV 走浏览器下载（Android 落到「下载」目录） | 约半天；中文表头需加 BOM 否则 Excel 乱码；老人基本不会用，只服务家属 |
| D3 一键复制为文本 | 点一下把近 30 天记录复制到剪贴板，粘到微信发给子女 | 最轻（约 1 小时）；不可分析、不可归档，记录多了很乱 |

**我的推荐**：**D1 暂不做**。理由：V1 唯一使用者是爸爸，导出是家属的次级需求；`PRODUCT_PLAN` 已把数据导出列在 P2/可延后；现在多做一个按钮就多一处真机要测的交互，先保证安装、语音、息屏三件事在真机上过。schema 不改，将来加 D2 不返工。

**若不选则默认**：不做导出，仅在设置「关于」保留一行「训练记录只保存在本机，不会上传」。

## E 部署与发布授权

**决策**：用哪条链路把 App 送到爸爸手机上，以及授权我做哪些 Git / 远端操作。

| 选项 | 说明 | 代价 |
|---|---|---|
| E1 本地托管（先做） | `npm run build` 后用 `adb reverse` 把手机 localhost 指到电脑端口，手机浏览器打开即安装 | 电脑关机就没了，只适合验收；需一根 USB 线；不能长期给爸爸用 |
| E2 GitHub Pages（正式） | push 到 main 触发 Actions，得到 `https://wanghoufan.github.io/p064-muscle-guardian/` 固定链接 | 需授权 commit + push；仓库要 public（免费版）；页面公开可访问（内容无隐私，仅前端代码） |
| E3 腾讯云/国内静态托管 | 大陆访问更稳，加载更快 | 需额外账号、配置；绑自定义域名要备案；与 062 复用链路不一致，成本最高 |

注：局域网 `http://192.168.x.x` 打开**不能**注册 Service Worker，安装与离线测不出来（浏览器只信 https 与 localhost）；E1 必须用 `adb reverse` 或 https，否则只能测界面不能测「可安装 + 断网」。

**需要你授权的四件事**（逐条勾）：① 允许我本地 `git commit`；② 允许 `git push` 到 `origin/main`；③ 允许在仓库里加 `.github/workflows/pages.yml` 并开启 Pages；④ 仓库保持 public（或用你自己的私有仓库 + 你手动开 Pages）。

**我的推荐**：**先 E1 跑通安装与离线，再 E2 出正式链接**。理由：E1 不碰远端，出问题只影响本机；E2 与 062 的 `prepare-web.cjs` + Pages 链路完全一致，复用成本最低，https 天然满足安装条件；E3 只有在你明确要求「大陆打开要快」时才值得做。

**若不选则默认**：只做 E1，不 commit、不 push、不建工作流；构建产物留在本地，验收后由你决定是否发布。

## F 爸爸手机类型

**决策**：确认爸爸实际用的手机，用于真机 QA 与给他写「一步一句」的安装说明。

| 选项 | 说明 | 代价 / 影响 |
|---|---|---|
| F1 小米 / Redmi（MIUI、HyperOS） | 与 `PRODUCT_PLAN` A1 假设一致（小米 Note11 5G） | 最省事，QA 与文案可直接照假设写；自带浏览器需手动「添加到桌面」 |
| F2 华为 / 荣耀（HarmonyOS，可能无 GMS） | 国产 ROM，浏览器与 TTS 差异大 | 中文语音大概率有，但需实测；安装引导走「华为浏览器 → 添加到桌面」 |
| F3 OPPO / vivo / 三星等 | 各家浏览器行为不同 | 需按实际机型写引导；三星需确认是否装 Chrome |
| F4 不确定 | 让爸爸拍一张「设置 → 关于手机」截图 | QA 前必须补，否则安装说明只能写通用版 |

请回答这 5 个具体问题：
1. **品牌 + 型号**（例：Redmi Note 11 5G / 华为 nova 12 / OPPO A2）
2. **Android 版本**（设置 → 关于手机 → Android 版本，如 13；华为填 HarmonyOS 版本）
3. **常用浏览器**是哪个（自带浏览器 / Chrome / 微信内打开）
4. 是否允许**安装未知来源应用**（本项目是 PWA 不需要，但影响是否额外给 APK 兜底）
5. 屏幕大概多大（6.5 英寸左右即可，用于核对 360×640 不溢出）

**我的推荐**：**F1 小米/Redmi + Android 12 及以上 + 用 Chrome**。理由：`PRODUCT_PLAN` 的 A1/A5 假设（Wake Lock 可用、Chrome 支持「添加到主屏幕」）就是按这条写的，QA 脚本、语音降级策略、安装截图都能直接复用；小米系也是老人机保有量最高的。

**若不选则默认**：按「小米 Note11 5G / Android 12 / Chrome / 允许安装」执行真机 QA 与安装说明，拿到真机型后只补测差异项（语音可用性、添加到桌面入口位置）。
